00 Project Overview

This repository contains the full implementation for a Master's thesis on pricing and calibrating Bitcoin inverse options using the rough Bergomi (rBergomi) stochastic volatility model. The work covers three components:

  • Theoretical: Extending rBergomi (Bayer, Friz & Gatheral 2016) to inverse options — crypto-native derivatives where payoffs are denominated in the underlying asset (BTC).
  • Empirical: Calibration on 22 Deribit snapshot dates spanning 2022–2025, across 7 market events (LUNA, FTX, SVB, ETF approval, Halving, BTC $100k, Trump inauguration) and 3 volatility regimes.
  • Computational: Three simulation pipelines compared — Cholesky+Euler, Hybrid+Euler (BLP 2017), Hybrid+Mixed Estimator (MP 2018) — with Numba JIT acceleration.

02 Core Library: src/rbergomi/

Self-contained Python package implementing the rBergomi model for inverse crypto options. Designed to be importable independently of the thesis pipeline.

pricer.py — rBergomiPricer

Monte Carlo pricer with two fBm simulation schemes:

  • CholeskyScheme: exact covariance matrix factorisation — O(n²) memory
  • HybridScheme: kernel decomposition (BLP 2017) — O(n·κ), stable for any n_steps

Pricing methods: log-Euler spot MC or Mixed Estimator (MP 2018, conditional BS — no spot path noise). Numba JIT on hot loops for 10–50× speedup.

calibrator.py — Calibrator

Two-phase optimization for (H, eta, rho):

  • Phase 1: Differential Evolution (2k paths, global search)
  • Phase 2: Nelder-Mead refinement (10k paths, local polish)

Forward variance xi_0(T) is pre-computed from ATM IVs (not a free parameter). Loss function uses maturity-aware weighting (1/√T).

mixed_estimator.py — MixedEstimator

McCrickerd & Pakkanen (2018) variance reduction technique. Prices as conditional Black-Scholes given the variance path, eliminating spot-path Monte Carlo noise. Combined with antithetic sampling: 10–50× effective speed-up vs. plain Euler MC.

utils.py — Utilities

  • bs_price_inverse_put/call() — Black-Scholes for inverse payoffs (denominated in BTC)
  • implied_vol_brent() — IV inversion via Brent's method
  • batch_implied_vols() — vectorized IV computation
  • Performance timer and European-number formatting

visualizer.py — CalibrationVisualizer

  • Smile fit plots (IV by maturity, model vs. market)
  • Residuals heatmap (moneyness × maturity grid)
  • Residuals histogram with normality overlay
  • 3D IV surface (matplotlib surface plot)
  • LaTeX table generation from CalibrationResult

Three Simulation Methods Compared

Cholesky + Euler

Exact fBm simulation via covariance matrix factorisation. Baseline reference. Diverges for n_steps > 50.

Hybrid + Euler

Kernel decomposition (BLP 2017). Stable for any n_steps. Better speed/accuracy trade-off than Cholesky.

Hybrid + Mixed ✓ Best

Mixed Estimator (MP 2018) on top of Hybrid fBm. Lowest RMSE, fastest convergence. Selected as primary method.

04 Statistical Analysis Scripts

compare_h_bounds.py

Sensitivity analysis of the Hurst parameter lower bound. Compares H ∈ {0.01, 0.001, 1e-4} across all methods and dates.

  • Loads CSV tables from each H-bound variant
  • Computes parameter shift (ΔH, Δeta, Δrho) and RMSE change
  • Prints per-date comparison tables

python main_c.py --compare-h-bounds [--method M]

residual_analysis.py

Formal statistical tests of calibration residuals to validate model fit.

  • Re-runs pricer with calibrated parameters to get per-point model IVs
  • One-sample t-test: H₀: mean(residuals) = 0
  • Wilcoxon signed-rank: H₀: median(residuals) = 0 (non-parametric)
  • Reports bias_pp per date for all 3 methods

python main_c.py --residual-analysis [--method M]

compare_xi_approaches.py

Compares two approaches for the forward variance curve xi_0(t):

  • Naive: xi_0(T_k) = sigma_ATM(T_k)² — biased upward
  • Bootstrap: solves E_Q[V_T] = xi_0(T) iteratively — unbiased

Generates IV surface comparisons, bias-by-maturity plots, and speed benchmarks.

python main_c.py --compare-xi [--method M]

fix_calibration_bias.py

Deep-dive into the systematic upward IV bias arising from naive xi_0(t) initialization. Proposes and tests a bootstrap correction that solves E_Q[V_T] = xi_0(T) numerically. Includes cross-method summary plots.

python main_c.py --fix-bias [--method M]

05 Key Design Decisions

xi is a pre-computed curve, not an optimizer parameter. The forward variance xi_0(T_k) is extracted from ATM IVs before optimization. This reduces the optimizer's search space from 4 to 3 parameters (H, eta, rho) and avoids degeneracy between xi and eta. Class: ForwardVarianceCurve in calibrator.py.
H is always jointly optimized. The thesis does not fix H at a prior value. All three parameters (H, eta, rho) are jointly estimated via DE + Nelder-Mead on each snapshot surface. This avoids identification bias.
ATM identification uses delta-neutral (d1 ≈ 0), not moneyness ≈ 1. For inverse options the ATM point shifts with IV level. Using d1 = 0 ensures the ATM IV extraction is model-consistent and avoids a systematic bias in xi_0(T).
Loss function weights by maturity (1/√T). Short-dated options constrain eta and rho more strongly (higher vega sensitivity). Down-weighting long-dated options prevents the optimizer from ignoring the near-term smile shape.
Hybrid + Mixed Estimator selected as primary method. Hybrid scheme is numerically stable for any n_steps (Cholesky diverges for n_steps > n_coarse). Mixed Estimator eliminates spot-path MC noise, giving 10–50× speed-up over Euler MC for the same RMSE target.

06 Thesis Structure (LaTeX)

The thesis (Tesi_Magistrale_rBergomi.pdf) is organized in three chapters.

Chapter 1 — Cryptocurrency Derivatives & Inverse Options

  • Bitcoin as a financial asset: stylized facts, fat tails, excess kurtosis (Student-t fit to log-returns)
  • Deribit exchange and BTC option market structure
  • Inverse options: payoff = max(1/K − 1/S_T, 0) in BTC. Pricing: Black-Scholes in BTC numéraire.
  • Greeks of inverse options vs. direct options: Delta, Gamma sign reversal; Vega asymmetry. Based on Alexander, Imeraj & Tarim (2023).
  • IV surface characteristics: steep put skew, short-dated term structure inversion during crypto stress events

Chapter 2 — Rough Volatility & rBergomi Model

  • From BSM to stochastic volatility: motivation via volatility smile and term structure
  • Rough volatility: Gatheral et al. (2018) — empirical evidence that H ≈ 0.1 in realized volatility data
  • rBergomi model: V_t = ξ₀(t)·exp(η·Z^H_t − ½η²·t^{2H}), Z^H fractional BM with Hurst H
  • Simulation schemes: exact Cholesky vs. Hybrid kernel decomposition (Bayer, Lux & Pakkanen 2017)
  • Mixed Estimator / Turbocharging: McCrickerd & Pakkanen (2018) variance reduction for inverse options
  • Forward variance curve ξ₀(t): relationship to ATM IVs, bootstrap construction

Chapter 3 — Empirical Calibration on Bitcoin Options

  • Data: Deribit BTC inverse options, 22 snapshot dates, 2022–2025
  • Calibration events: LUNA collapse (May 2022), FTX (Nov 2022), SVB (Mar 2023), BTC ETF approval (Jan 2024), Fourth Halving (Apr 2024), BTC $100k (Dec 2024), Trump Crypto EO (Jan 2025)
  • Baseline regimes: 3 dates each for low / medium / high ATM IV
  • Calibration methodology: DE (coarse, 2k paths) + Nelder-Mead (fine, 10k paths). Quality flags: good / acceptable / borderline / poor.
  • Three method comparison: Cholesky+Euler vs. Hybrid+Euler vs. Hybrid+Mixed (RMSE, speed, parameter stability)
  • Statistical validation: t-test and Wilcoxon signed-rank on calibration residuals
  • H sensitivity: lower-bound analysis (0.01 / 0.001 / 1e-4)

Event Highlights

  • FTX Collapse (2022-11-09): H drops to ~0.05, η spikes to ~3.0, ρ ≈ −0.82. Largest calibration challenge; RMSE ~3.5 pp.
  • ETF Approval (2024-01-10): H rises to ~0.12 (less rough), positive skew inversion partially. η ~1.6.
  • BTC $100k (2024-12-05): Low ATM IV (baseline-like), H ~0.08, very stable calibration.
  • Low-IV baseline: Best calibration quality (RMSE < 1.8 pp), confirming rBergomi fits quiet markets well.
